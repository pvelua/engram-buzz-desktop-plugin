# v0.2.0

Your Buzz Desktop agents now wake by themselves when ENGRAM has something for them, such as findings another agent handed them, and ENGRAM keeps a record of each task they finish.

## What's new

- **Wake** an agent when an item waits for it in its ENGRAM inbox, such as a hand-off, an approval or a project change. The agent wakes in the channel bound to its project, and nobody has to mention it.
- **Act** on an inbox item with `engram_inbox` and `engram_inbox_act`. An agent can use only the actions ENGRAM offers for that item.
- **Hand off** findings to another agent with `engram_hand_off`. They land in that agent's inbox, and once it accepts them they become its memories.
- **Record** each finished task in ENGRAM with `engram_turn`: the outcome, the reply that delivered it, what started the task, and the skill the agent worked under.
- **Keep** what an agent read out of the task record: the record lists what the agent looked up in ENGRAM, but never the contents.
- **See** where an agent's wake-ups will go: the **Test** button on its ENGRAM card now names the channel, or says why wake-ups are off.
- **Choose** a different channel for an agent's wake-ups with the optional **Inbox wake-ups channel (override)** field.

## Before you start

1. Install Buzz Desktop 1.0.5 or later, and this plug-in.
2. Give each agent its ENGRAM identity in Settings → ENGRAM: a restricted PAT and a project.
3. In Buzz Desktop, add ENGRAM to the channel where your agents work.
4. In ENGRAM, bind that channel to the project. Add ENGRAM to the channel first; otherwise the channel can take up to five minutes to start working.
5. Press **Test** on each agent's card, and check that it names the channel.

## Known limits

- Agents run only while Buzz Desktop is open.
- The ENGRAM PAT is kept in the plug-in's storage on this computer, not in the Keychain; use a restricted PAT.
- An agent wakes about a minute after an item arrives in its inbox, because the plug-in checks once a minute.
- Only items waiting for the agent wake it. A decision on something the agent submitted does not.
- A task is recorded only when the agent reports it. The record has no token usage and none of the model's reasoning, because Buzz Desktop does not give those to a plug-in.
- ENGRAM's **Test agents** cannot reach Buzz Desktop agents. This is expected, and wake-ups still work.
